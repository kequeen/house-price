# 数据架构与维护

## 数据链路

官方HTTPS网页 → 限速读取与内容快照 → 标题/期间/表头/完整性校验 → 幂等观测写入 → API序列与缺失对齐 → 图表和来源导出。

国家统计局目录页按时间分页发现公告，避免猜测文章编号。公告同时有桌面和移动版表格，内容一致才合并，冲突或不足70城时整月拒绝入库。只解析表1/表2总指数，面积分档表不混入。2005等更早历史未沿用旧项目数据。

## 表与业务约束

- `cities`：城市名称、国家统计局分类、省份。采集70城，前端聚焦35个一二线城市。
- `source_documents`：官方URL与SHA256共同唯一。保留每个已入库文档版本，快照按内容哈希存储。
- `price_observations`：`city + period + house_type + provider`唯一；只存原始环比和同比指数，不存虚构均价。观测指向当前来源版本，旧来源版本仍可下载。
- `housing_observations`：`city + period + frequency + house_type + scope + provider`唯一；数量和面积独立可空，零与空区分；地理范围明确保留，不存未知成交金额。
- `sync_runs`：数据库部分唯一索引限制一个运行任务。状态为running/succeeded/partial/failed，有心跳、计数和具体错误。
- `schema_versions`：独立官方库schema v1。新版本应增加显式迁移，不依赖`create_all`升级已有列。

一次公告的观测和来源写入同一个事务。重复内容不重复插入；官方修订更新事实所关联的来源，旧文档保留。源站读取失败不会清空已有观测。价格与住建数据互不覆盖。

## 计算与展示

同比/环比变化：官方同比/环比指数减100，单位百分比。

相对指数：起始月设100，其后逐月乘官方环比指数/100。所有所选城市使用同一个起始月；基准月缺失则整段不计算，任何中间缺失导致后续累计值为空。不是官方定基指数，不插值，也不把指数当元/平方米。

国家统计局每5年基期及权数有调整；2026年起使用2025年作为新基期。跨基期累计曲线需结合官方说明，不能替代对固定房屋样本价格的估计。

住建表的月、年分别查询。石家庄新房使用商品房“其中住宅”列，二手房使用“存量住房”列；分区求和与合计差超过0.1则拒绝入库。北京使用有明确月份的住宅签约列，年度原表万套/万平方米换算为套/平方米。网页采集日从不用于代替数据期间。

## 扩展地方住建数据

1. 找到无需登录且可公开读取的官方表格；核验是否住宅、网签或登记、自然月或累计、是否全市、单位。
2. 保存真实HTML回归样本，编写解析器；缺失/挑战页/错误月份必须拒绝入库，不输出零值。
3. 在`catalog.py`登记渠道，在同步流程调用解析器和`ingest_housing`。用scope保留口径，不覆盖其他来源。
4. 验证至少两个月、重复抓取及异常返回，再把状态从尚未接入变成可同步。

HTTP客户端只接受已登记的HTTPS官方主机，不跟随未知重定向，使用TLS校验、连接/读取超时、三次网络重试、5MB页面上限及至少0.35秒请求间隔。不会破解动态验证，也不读取个人成交信息。

## 运行

默认本机127.0.0.1监听，SQLite同步任务锁跨API和CLI生效。后台同步在普通函数线程中执行，不阻塞异步事件循环。前端查询用请求序号防止快速切换城市/月份后旧响应覆盖新选择；图表卸载释放实例和ResizeObserver。

原始HTML以附件下载，避免在应用域执行源站脚本。生产部署需要独立评估认证与任务调度，此版本定位本地单用户研究。
